SITE REPORT

My Web Development Experience

A reflection on my learning, development and design process.

My Learning Experience

At the beginning of this module, I had a basic understanding of HTML and CSS, but I was not very confident about creating a complete website by myself. Building this portfolio helped me understand how different parts of a website work together. I started by learning the basic structure of HTML and then used CSS to control the layout, colours, spacing and typography of the pages.

One of the things I found useful was learning about semantic HTML. Instead of using div elements for everything, I learned to use elements such as header, nav, main, section, article, footer, figure and table where they were appropriate. This made my code easier to understand and also helped me follow the requirements of the assignment.

Development of My Website

I developed the website step by step instead of trying to complete every page at once. I started with the home page, which introduces me as a Computer Science student. After creating the basic navigation, I developed the Projects page, Skills page, Blog page and Contact page.

The Projects page uses a grid layout to display different projects. The Skills page uses lists and tables to present my technical skills, education and Google-related learning. For the Blog page, I chose mountains as the topic and used images together with text. The Contact page includes my contact details and a simple message form.

Design Decisions

I wanted the website to look simple and suitable for a student portfolio rather than looking like a complicated professional template. I used a dark navy colour for the navigation and footer because it gives the pages a clear structure. I used white backgrounds for most of the content so that the text is easy to read.

I used a simple Arial font for most of the website because it is easy to read on both desktop and mobile screens. For some large headings I used a serif style to create a small difference between headings and normal text.

I also kept the same navigation, colours and general spacing throughout the pages. This gives the website a consistent user interface and makes it easier for visitors to move between the different pages.

My Ups and Downs

One of the difficult parts of the development was getting the layout to look correct on different screen sizes. At first, some elements looked fine on my computer but did not fit properly when the browser became smaller. I had to learn about media queries, flexible widths and CSS Grid to improve the responsive design.

I also had problems with the navigation menu and the active page link. Sometimes the wrong page appeared to be active because I had forgotten to change the class on a different HTML page. Debugging these small problems helped me understand that even simple websites require careful checking.

Another useful part of the project was working with JavaScript. I used a small amount of JavaScript for the mobile navigation and the Contact page. The contact form displays a thank-you message after it is submitted. This helped me understand how HTML, CSS and JavaScript can work together.

Responsive Design and Testing

I tested the website using different browser window sizes to make sure that the content remained readable. The navigation changes for smaller screens and the project and blog layouts change from multiple columns to a single column. Images also resize so that they do not overflow the page.

I also checked the links between all pages and tested the contact form. I used HTML and CSS validation tools to find coding errors and make improvements to my website.

Validation

I used the W3C Nu Html Checker to validate every page of my website. Each page was uploaded individually and checked against current HTML standards. The screenshots below show that all six pages passed with no errors or warnings.

Design Inspiration

While developing the website, I looked at simple student portfolio websites and modern personal websites for ideas about navigation, spacing, typography and page structure. I did not copy a complete website. Instead, I used these websites as inspiration and changed the layout and content to suit my own portfolio.

One of my main goals was to keep the design simple and easy to navigate. I preferred a clean white background with a dark navigation bar rather than using too many colours or decorative elements.

GitHub Development

I used Git and GitHub to keep track of the development of my website. I made commits when I completed or changed important parts of the website, such as the home page, projects, skills, blog and contact pages. This allowed me to keep a record of my progress instead of uploading the whole website only at the end.

GitHub was also useful when I needed to check previous versions of my work. If I made a change that caused a problem, I could compare the changes and understand what needed to be corrected.

Final Reflection

Overall, this module has helped me become more comfortable with web development. I have learned that creating a website is not only about making it look good. The structure of the HTML, the organisation of CSS, accessibility, responsiveness, validation and testing are also important. I still have areas that I need to improve, especially JavaScript and more advanced responsive design, but I feel more confident than I did at the beginning of the module.

The portfolio is a record of what I have learned so far. There are parts that I would improve in the future, but building the website and solving the problems along the way has given me useful practical experience.
